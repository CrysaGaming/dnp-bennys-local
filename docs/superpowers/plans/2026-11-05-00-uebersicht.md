# Benny's Portal – Implementierungsplan: Übersicht

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Das interne Mitarbeiterportal „Benny's“ (DNP Roleplay) laut Spec bauen, in 11 Phasen, die jeweils lauffähige und getestete Software liefern.

**Architecture:** Next.js 16 App Router mit Server Components und Server Actions. Fachlogik liegt in `src/features/<modul>/service.ts`; jede Funktion bekommt einen `SessionContext` und prüft ihre Rechte selbst. Die Server Actions sind dünne Wrapper. PostgreSQL über Prisma 7 mit `@prisma/adapter-pg`, Auth über Better Auth (Username, Admin, Next-Cookies).

**Tech Stack:** Next.js 16.4, React 19.3, TypeScript strict, Tailwind CSS 4.3, shadcn/ui, Prisma 7.10.1, PostgreSQL 17, Better Auth 1.7, zod 4, motion 14, next-themes 0.4, Vitest 5, Playwright 1.64, Node 26.

**Spec:** `docs/superpowers/specs/2026-11-05-bennys-portal-design.md`

## Global Constraints

Diese Regeln gelten für jede Aufgabe in jeder Plan-Datei.

- **Versionen exakt pinnen** (`--save-exact`): `next@16.4.5`, `react@19.3.1`, `react-dom@19.3.1`, `tailwindcss@4.3.4`, `prisma@7.10.1`, `@prisma/client@7.10.1`, `@prisma/adapter-pg@7.10.1`, `better-auth@1.7.17`, `zod@4.6.7`, `motion@14.9.1`, `next-themes@0.4.6`, `sonner@2.0.8`, `vitest@5.1.0`, `@playwright/test@1.64.1`. **Nie** `prisma@latest` installieren: Der Tag zeigt auf `8.0.0-rc.30`.
- Node 26 (lokal `v26.1.0`, Docker `node:26-alpine`). npm als Paketmanager.
- `src/proxy.ts` statt `middleware.ts`. Der Proxy prüft nur den Session-Cookie und leitet **nie** von `/login` weg.
- UI-Texte Deutsch, Code-Bezeichner Englisch.
- Zahlen im deutschen Format: `$12.500`, `1,5 kg`. Formatierung nur über `src/lib/format.ts`.
- Geld: `Int` in ganzen Dollar. Gewicht: `Int` in Gramm. Zeiten in UTC speichern, in `Europe/Berlin` anzeigen.
- Jede schreibende Fachfunktion: zod-Validierung → `assertPermission` → DB-Transaktion → `writeAudit`.
- Kein Hard-Delete außer `Resource` und Kunden ohne Aufträge und Treue-Buchungen.
- Öffentliches Repo: keine Secrets und keine RP-internen Werte (Funk-Kanal, Funk-Passwort, Admin-Zugang) in Code, Seed, Tests oder Doku. Werte kommen aus Umgebungsvariablen. In Tests gelten Platzhalter wie `1234` und `0000`.
- Keine Rockstar-Assets (Logos, Artworks, Schriften).
- `prefers-reduced-motion` und `UserPreference.reducedMotion` schalten alle Bewegungen auf Opacity-Fades um.
- Die Login-Seite ist immer dunkel.

## TDD-Zyklus pro Aufgabe

Jede Aufgabe folgt diesem Ablauf. Die Plan-Dateien nennen pro Aufgabe nur Tests, Signaturen und Befehle.
1. Test schreiben (Namen und Assertions stehen im Plan).
2. Test ausführen, er muss rot sein.
3. Minimal implementieren.
4. Test ausführen, er muss grün sein. Dazu `npm run typecheck` und `npm run lint`.
5. Commit mit Conventional-Commit-Präfix (`feat`, `fix`, `test`, `chore`, `docs`) und deutschem Text, z. B. `feat(kunden): Kennzeichen normalisieren`.

## Review Focus

Diese Eingaben deckt die Spec nicht ausdrücklich ab. Sie gehen am ehesten schief, darum hat jede einen eigenen Test in der genannten Aufgabe.

1. **Gewichtseingabe mit Punkt:** „1.500“ in das Gewichtsfeld. Erwartung: 1,5 kg (1500 g), weil der Punkt als Dezimaltrenner gilt. Nach dem Speichern zeigt die Tabelle „1,5 kg“. → Plan 04, Task 7.1.
2. **Doppelklick oder zwei Tabs:** zweimal Einstempeln oder dieselbe Prämie in zwei offenen Aufträgen einlösen. Erwartung: Der zweite Versuch scheitert mit klarer Meldung, kein Konto wird negativ. → Plan 03, Task 5.1 und Plan 05, Task 8.2.
3. **Veraltetes Session-Cookie** nach Sperrung: Erwartung: `/dashboard` leitet genau einmal auf `/login`, `/login` rendert ohne Schleife. → Plan 01, Task 1.4.
4. **Kennzeichen mit Kleinbuchstaben und Leerzeichen:** „  8ben  42 “. Erwartung: gespeichert als `8BEN 42`. Eine zweite Eingabe „8BEN 42“ wird als Dublette erkannt. → Plan 05, Task 8.1.
5. **Aussperren des letzten Admins:** den letzten aktiven Admin sperren, herabstufen oder dem Admin-Rang Rechte entziehen. Erwartung: wird abgelehnt mit Hinweis. → Plan 03, Task 4.1 und 4.3.
